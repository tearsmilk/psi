# ADR-004 · Стек команд: копии «до/после», стабильные id, макросы и лимиты

**Статус:** принято (этап 00).

## Контекст

Отмена/повтор должны быть надёжными для любых инструментов, включая массовые операции и ассоциативные размеры, которые
ссылаются на объекты по id.

## Решение

- `Command` с `redo(Document&)` / `undo(Document&)`; `CommandStack::push` сразу выполняет `redo`.
- `EntityCommand` хранит полные копии объектов (добавленные, удалённые, пары до/после). Id добавленных объектов фиксируются
  при первом `redo` и переиспользуются при повторе — ссылки размеров (`refs`) остаются валидными.
- Отдельные команды для слоёв, листов и настроек; `MacroCommand` объединяет шаги инструмента (например, демо-сценарий).
- Лимиты: 200 команд / 256 МБ (`memory()`), индекс «чистого» состояния для признака «не сохранено».
- Переключатели вида (сетка, привязка, орто) намеренно не попадают в стек.

## Отвергнуто

- `QUndoStack`: нет лимита по памяти, нет доступа к документу в командах без синглтонов, сложнее тестировать без GUI.
- Дельты вместо копий: экономят память, но резко усложняют корректность для составных объектов; копии объектов в мм —
  сотни байт, лимит памяти решает проблему.

## Последствия

Любая правка документа в UI обязана идти через команду (см. CONTRIBUTING.md). Импорт DXF — одна команда, отменяемая целиком.
