# Архитектура Пси (этапы 00–01, 02 «Эскиз», 05 «Интерьер»)

```
apps/psi-desktop ──► psi_ui (rendering, modules/draft, sketcher/sketch_view, interior/interior_view, io/pdf, ui)
                        └──► psi_core (core, modules/drawing, modules/sketcher/sketch, modules/interior/building, io/native, io/dxf)
                                                                           │
                                                                           └── только Qt Core + zlib: без GUI, тестируется headless
```

## Слои

- **core/geometry** — `Point`/`Vec`, `Rect`, аффинный `Transform`, единая структура `Entity` с `EntityType`
  (Line, Polyline с bulge, Circle, Arc, Ellipse, Spline (Catmull-Rom), Hatch, Text, Leader, Dimension). Все операции —
  свободные функции: `flatten`, `segments`, `hitDistance`, `snapPoints`, `intersections`, `offsetEntity`, `trimEntity`,
  `extendEntity`, `filletLines`, `chamferLines`, `explode`, `dimensionValue` / `dimensionGeometry` (ассоциативные размеры
  через `refs`), JSON-сериализация.
- **core/units** — модель в мм; `Units::format/parse` для мм/см/м/дюймов, дробей, футов.
- **core/attributes** — типизированные атрибуты (`AttrKind`), хранятся на объектах и в основной надписи.
- **core/document** — `Document`: объекты в `unordered_map` + порядок вставки, `SpatialIndex` (равномерная сетка 100 мм,
  «большие» объекты отдельно), слои, листы, настройки; сигналы об изменениях с id.
- **core/command-system** — `CommandStack` с `EntityCommand` (add/remove/modify, стабильные id при redo), команды слоёв,
  листов, настроек, макросы, лимиты по числу и памяти, индекс «чистого» состояния.
- **core/project** — `Project`: документ + стек + метаданные + «чужие» части архива; автосохранение по таймеру, восстановление,
  недавние файлы (QSettings).
- **modules/drawing** — листы: форматы A0–A6, масштабы, `SheetViewport` (окно модели ↔ рамка на листе), `TitleBlock`.
- **modules/draft** — `Tool` (конечный автомат: `click/move/enter/escape/input/draw`), 30 инструментов, `SnapEngine`
  (конец, середина, центр, квадрант, пересечение, перпендикуляр, касательная, сетка; орто/полярное), `InputParser`
  (AutoCAD-подобный ввод), `Demo` (сценарий §22).
- **rendering** — `Renderer` (QPainter, косметические перья по толщине в мм × px/mm, штриховка, текст без зеркалирования,
  листы с рамкой и основной надписью), `Viewport` (кеш статического слоя в QPixmap, пакетирование линий по перу,
  оверлей: выделение с ручками, призрак инструмента, рамка выбора, маркер привязки, перекрестие; пан/зум; выбор рамкой
  внутрь / пересечением).
- **io/native** — `.psi` (см. formats/psi.md). **io/dxf** — ASCII DXF AC1015 (см. formats/dxf.md). **io/pdf** —
  `QPdfWriter` 1200 dpi, страница точного размера, MediaBox переписывается в точные пункты.
- **modules/sketcher** — параметрический эскиз (см. ниже): `Sketch` с примитивами и ограничениями, решатель, `SketchView`.
- **modules/interior** — модель здания (см. ниже): `Building` → `Floor` → стены / проёмы / мебель, помещения, ведомости,
  `InteriorView` (план этажа).
- **ui** — `Theme` (палитра светлая/тёмная, акцент, QSS), `Icons` (все глифы рисуются QPainter'ом, без ресурсов),
  `CanvasWidget` — общий 2D-холст (пан/зум, сетка, магнит к сетке) для «Эскиза» и «Интерьера».
- **apps/psi-desktop** — `MainWindow` (меню, панель рабочих областей, доки Инструменты / Дерево / Свойства / Слои,
  командная строка, строка состояния, горячие клавиши из QSettings, drag&drop), `SheetsPage`, `SketchPage`, `InteriorPage`,
  диалоги, `WelcomePage`, `--selftest` (`selftest.cpp` + `selftest_modules.cpp`).

## Эскиз: модель и решатель (`modules/sketcher`)

- **Модель.** `SketchEntity` — точка (x, y), отрезок (x1, y1, x2, y2), окружность (cx, cy, r), дуга (cx, cy, r, a0, a1);
  флаги `construction` (не выдаётся в чертёж) и `fixed` (все параметры закреплены). `Constraint` ссылается на объекты
  через `Ref {entity, point}` (point = −1 — весь объект, иначе индекс характерной точки: концы отрезка, центр, начало/конец
  дуги). 16 типов: совпадение, горизонталь, вертикаль, параллельность, перпендикулярность, касание (отрезок–окружность,
  окружность–окружность), равенство, закрепление, расстояние (точка–точка, точка–отрезок), длина, радиус, диаметр, угол,
  точка на линии, точка на окружности, симметрия.
- **Невязки.** Каждое ограничение даёт 1–2 скалярных функции `f(params) → 0`; угловые невязки умножаются на `kAngScale = 100`,
  чтобы радианы были сопоставимы с миллиметрами. Якобиан численный (центральные разности), разреженный: строка зависит
  только от параметров объектов, на которые ссылается ограничение.
- **Решатель.** Гаусс–Ньютон с демпфированием Левенберга: `(JᵀJ + λI) dx = −Jᵀr`, система решается методом сопряжённых
  градиентов без сборки плотной матрицы; λ уменьшается при успешном шаге и растёт при неудачном. Регуляризация
  «минимального изменения» — старт из текущего положения и малый шаг, поэтому при перетаскивании геометрия двигается
  плавно, а не перескакивает в другое решение. Остановка: |r|∞ < 1e-9 или 60 итераций. Если не сошлось, ограничения с
  |r| > 1e-4 помечаются `conflict` и подсвечиваются красным; `SolveResult::conflicts` — их id.
- **Степени свободы.** `degreesOfFreedom()` = число свободных параметров − ранг якобиана (модифицированный Грам–Шмидт по
  строкам, порог 1e-6 относительно нормы строки). Параметр закреплён ⇔ его единичный вектор лежит в пространстве строк,
  отсюда `freeEntities()` — раскраска холста (чёрное — определено, терракотовое — есть свобода). Ранг кешируется по
  ревизии эскиза и считается не чаще раза в кадр.
- **Производительность.** Перерешение при перетаскивании для 200 отрезков с 500 ограничениями — около 2 мс
  (`test_sketcher::perf200`, порог 10 мс — предупреждение, не ошибка).
- **Инструменты и UI.** `SketchView` (на `CanvasWidget`): отрезок, полилиния, прямоугольник (четыре отрезка + совпадения +
  H/V), окружность, дуга, точка; выбор точек и объектов (Shift — добавить), ограничения на выбор по кнопкам или клавишам
  `C H V P N T = F D L`; размерные подписи перетаскиваются, двойной клик — ввод значения и перерешение; «Автопривязки»
  добавляют совпадение концов и H/V при рисовании; «Магнит к сетке» притягивает курсор к узлам сетки.
- **Хранение.** `sketches/<id>.json` внутри `.psi` через «чужие части» проекта (`Project::foreignParts`) — схема `.psi`
  не меняется, старые версии Пси сохраняют эскизы как есть. Отмена на странице — снимками JSON (`SnapshotStack`).
- **Выдача в чертёж.** `Sketch::toDraftEntities()` → отрезки / окружности / дуги на текущем слое одной `EntityCommand`
  (отменяемо).

## Интерьер: модель (`modules/interior`)

- **Иерархия.** `Building` → `Floor` (имя, отметка, высота) → `Wall` (осевая полилиния, толщина, высота, материал),
  `Opening` (дверь: ширина, высота, петли слева/справа, открывание внутрь/наружу; окно: ширина, высота, подоконник;
  положение — расстояние вдоль оси стены, проём всегда остаётся на стене), `Furniture` (вид: шкаф / стол / полка /
  кровать / тумба; Ш×В×Г, поворот, материал, цвет, артикул, цена, полки / двери / ящики). Имена и материал пола
  помещений хранятся в `Floor::roomInfo` по ключу-центроиду (`roomKey`, шаг 100 мм), потому что сами помещения вычисляются.
- **Контуры стен.** Каждый сегмент — четырёхугольник со смещением ±t/2; в узлах с двумя сегментами углы «усами»
  (пересечение смежных смещённых рёбер).
- **Помещения.** Оси стен режутся по взаимным пересечениям, узлы склеиваются с допуском 1 мм, строится планарный граф;
  обход граней: в каждом узле соседи отсортированы по углу, из ребра u→v следующее — соседнее по часовой от v→u;
  грани с положительной площадью — помещения, «усы» (u→v, v→u) выбрасываются. Внутренний контур — смещение каждого
  ребра внутрь на половину толщины его стены; из него площадь (м²), периметр и центроид для подписи.
- **Коллизии.** Мебель–мебель и мебель–стена через разделяющие оси (SAT) выпуклых многоугольников.
- **Ведомости.** `furnitureSchedule` группирует по имени | артикулу | размеру | материалу | цене (количество, сумма);
  `materialSchedule` — площади стен (длина × высота) и полов (площадь помещений) по материалам; `csv()` — `;`-разделитель,
  UTF-8 с BOM при экспорте.
- **UI.** `InteriorView`: стена по оси с орто-подсказкой и магнитом к узлам, дверь / окно по щелчку на ближайшей стене с
  протяжкой вдоль неё, помещение (имя / материал пола), мебель из каталога (R — поворот на 90°), выбор / перенос /
  удаление, измерение длины и площади контура; план: штриховка стен, вырезы проёмов, дуга открывания, тройная линия
  окна, подписи помещений с площадью, условные знаки мебели, коллизии красным. `InteriorPage`: «Этажи и объекты»,
  «Свойства» (форма по типу выбранного), «Каталог мебели», «Ведомости» (две вкладки, «Экспорт CSV»).
- **Хранение и выдача.** `interior/<id>.json` в `.psi` (одно здание на проект); `Building::toDraftEntities(floor, doc)`
  создаёт слои «Стены», «Проёмы», «Мебель», «Помещения» и выдаёт контуры, двери с дугой, окна, мебель с подписью,
  подписи помещений одной командой.

## Потоки

Разбор DXF выполняется в рабочем `QThread` с `QProgressDialog` и отменой; результат применяется в главном потоке одной
командой (отменяемо). PDF-экспорт идёт в главном потоке с прогрессом и `processEvents` (QPainter на QPdfWriter).

## Производительность

- 50 000 линий: полный рендер < 300 мс на 2015 MacBook (в тестах бюджет 1500 мс для CI), окно-запросы к индексу ~мкс.
- Перерисовка при наведении/выделении не трогает кеш: только оверлей.
- `EntityCommand` хранит копии объектов «до/после»; стек ограничен 200 командами / 256 МБ.
