# Как вносить изменения

## Среда

- C++20, Qt 6.4+ (Core Gui Widgets PrintSupport Svg Test), CMake ≥ 3.21, Ninja, zlib. macOS 11+ Intel — целевая платформа;
  Linux подходит для разработки и тестов (`QT_QPA_PLATFORM=offscreen`).
- `cmake --preset debug && cmake --build --preset debug && ctest --preset release` (тестовый пресет использует офскрин).
- Сборка обязана быть без предупреждений (`-Wall -Wextra`), `QT_NO_KEYWORDS` включён: используйте `Q_SIGNALS`, `Q_EMIT`.

## Правила

1. **Единицы.** Модель всегда в миллиметрах; `Units` — только для отображения и разбора ввода.
2. **Изменения документа — только через команды** (`EntityCommand`, `LayerCommand`, `SheetCommand`, `SettingsCommand`),
   иначе ломаются отмена и признак «не сохранено». Исключение — переключатели вида (сетка, привязка).
3. **Форматы.** Любое изменение схемы `.psi` — увеличить `kSchemaVersion`, добавить миграцию в `PsiFile::read` и тест в
   `tests/formats/test_native.cpp`. Чужие части архива сохраняются как есть.
4. **UI.** Русский язык, стиль Claude (`ui/theme.cpp`). Новый экран / диалог / компонент — обновить
   `design/figma/01_ui_kit.js` / `02_screens.js` в том же изменении и выложить в Figma «Пси — UI».
5. **Тесты.** Новый инструмент — тест в `tests/integration/test_ui.cpp`; новая геометрия — `tests/unit/test_geometry.cpp`;
   производительность — бюджеты в `tests/performance/test_perf.cpp`. `psi --selftest` должен оставаться зелёным.
6. **Производительность.** Рендер через кеш `Viewport` и пакетирование по перу; пространственные запросы через
   `Document::query`; не вызывать `entityIds()` в горячих путях.
7. **Коммиты** — по-русски, в повелительном наклонении, один логический шаг на коммит.

## Стиль кода

`.clang-format` в корне (LLVM, 4 пробела, 160 колонок, короткие функции в одну строку допустимы). Заголовки — `#pragma once`,
пространство имён `psi`. Публичные типы — структуры с явными полями, без лишних геттеров.
